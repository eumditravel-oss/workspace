# WORKSPACE UI DESIGN PATCH 001  
## 페이지별 디자인 개선 및 승인 기반 단계 진행 프롬프트

이 문서는 `workspace plan1.txt`부터 `workspace plan16.txt`까지의 기능/데이터/권한 구조를 유지하면서, 현재 Workspace 화면의 디자인 완성도를 높이기 위한 **UI/UX 전용 패치 문서**다.

이 작업은 신규 기능 추가가 아니라 **기존 화면의 시각 품질, 정보 위계, 여백, 테이블, 카드, Empty State, 반응형 레이아웃을 개선하는 작업**이다.

---

# 0. 실행 원칙

Google Antigravity는 이 문서를 읽고 아래 원칙을 반드시 지켜야 한다.

1. 기존 `workspace plan1.txt`부터 `workspace plan16.txt`까지의 데이터 구조를 훼손하지 않는다.
2. 기존 권한 selector, 데이터 selector, JSON 운영 데이터 구조를 우회하지 않는다.
3. 디자인 개선 중 기존 기능을 삭제하지 않는다.
4. 페이지별 Phase 단위로만 진행한다.
5. 각 Phase 완료 후 사용자 승인 전까지 다음 Phase로 넘어가지 않는다.
6. 각 Phase마다 lint/build 검증을 수행한다.
7. 원격 GitHub push는 사용자 승인 전까지 절대 하지 않는다.
8. 마스터 리포트나 완료 보고서가 아니라 실제 코드와 화면 기준으로 완료 여부를 판단한다.

---

# 1. 현재 UI 문제 요약

현재 화면 기준으로 다음 문제가 확인된다.

1. 전체적으로 관리자용 SaaS 화면이라기보다 임시 테스트 UI처럼 보인다.
2. 상단 헤더에 `undefined - SUPER_ADMIN`이 표시된다.
3. 좌측 사이드바가 어둡고 무겁지만 정보 밀도가 낮다.
4. 페이지마다 콘텐츠 폭, 카드 폭, 테이블 폭이 제각각이다.
5. 검은색 테두리가 강해서 오래된 내부 시스템처럼 보인다.
6. 빈 화면이 많지만 안내 문구와 다음 액션이 부족하다.
7. 대시보드 통계 카드가 단조롭고 보조 지표가 없다.
8. 수주 프로젝트, 결재, 충돌, 알림, 설정 화면의 표 디자인이 촌스럽다.
9. 직원 일정표는 Excel 느낌이 강하고 현대적인 일정 관리 화면처럼 보이지 않는다.
10. 실사용 모드 / 운영 검증 모드 / 데이터 JSON 운영 상태가 시각적으로 정리되어 있지 않다.
11. 페이지별 제목, 필터, 액션 버튼 위치가 일관되지 않다.
12. 여백이 너무 많아 화면 활용도가 낮다.

# 2. 전체 디자인 원칙

## 2-1. 디자인 콘셉트

```text
Enterprise Project Operations Dashboard
```

실제 회사의 프로젝트, 일정, 결재, 충돌, 인사 데이터를 관리하는 운영형 SaaS 관리자 화면처럼 보여야 한다.

## 2-2. 디자인 토큰

다음 기준을 전역 스타일 또는 공통 CSS 변수로 정리한다.

```css
--color-bg: #F8FAFC;
--color-surface: #FFFFFF;
--color-border: #E5E7EB;
--color-border-strong: #CBD5E1;
--color-text-main: #0F172A;

--color-danger: #EF4444;
--color-warning: #F97316;
--color-info: #2563EB;
--color-success: #10B981;

--radius-card: 14px;
--radius-button: 10px;
--page-max-width: 1280px;
--page-padding-x: 32px;
--section-gap: 24px;
--card-padding: 20px;
```

## 2-3. 공통 UI 규칙

- 강한 검은색 border를 제거하고 연한 회색 border를 사용한다.
- 표는 검은 선 테이블이 아니라 modern table 스타일로 변경한다.
- 페이지별 콘텐츠 max-width를 통일한다.
- 카드, 테이블, 필터바, 섹션 헤더의 높이와 여백을 통일한다.
- Empty State에는 단순 문구가 아니라 다음 액션 버튼을 제공한다.
- 모든 페이지는 모바일/작은 화면에서도 최소한 깨지지 않게 한다.
- 기존 권한 selector, 데이터 selector를 우회하지 않는다.
- UI 개선 과정에서 기능을 삭제하지 않는다.

# Phase UI-01 — 공통 레이아웃, Topbar, Sidebar 디자인 개선

## 목표

전체 화면의 기본 골격을 먼저 정리한다.

## 작업

### Topbar 개선

- `undefined - SUPER_ADMIN` 표시 제거
- 회사/부서/역할 표시를 안전하게 fallback 처리

예시:

```text
본사 · 최고관리자
CON-COST · 구조팀 PM
Viet_QS · Slab Team 작업자
```

- 실사용 모드 / 운영 검증 모드 badge 디자인 정리
- 데이터 상태 badge 디자인 정리
  - `데이터: JSON 운영`
  - `데이터: Demo Seed`
  - `데이터: 비어 있음`
- 우측 역할 선택, 결재함, 성과평가, 알림, 사용자 영역 정렬

### Sidebar 개선

- 기본 폭을 220px 이하로 유지
- Mini 모드 52~64px 유지
- 메뉴 active 상태 개선
- 하단 접기 버튼 디자인 개선
- 메뉴명은 짧고 명확하게 유지

권장 메뉴명:

```text
대시보드
프로젝트
보드
결재
충돌
일정표
알림
설정
```

### Page Layout 개선

- 모든 페이지에 공통 `.page-shell` 적용
- max-width 1280~1440px
- 상단 여백, 좌우 여백 통일
- 과도한 빈 공간 축소

## 완료 조건

- `undefined` 문구가 더 이상 보이지 않음

# Phase UI-02 — 통합 대시보드 디자인 개선

## 목표

통합 대시보드를 실제 관리자용 관제 화면처럼 개선한다.

## 현재 문제

- 상단 `통합 대시보드` 박스와 `최고관리자 대시보드` 제목이 중복되어 보인다.
- 통계 카드가 단조롭다.
- `진행 중 프로젝트 요약` 표가 낡은 테이블처럼 보인다.
- 데이터가 없을 때 안내와 액션이 부족하다.

## 개선 방향

### 상단 헤더

```text
통합 대시보드
본사 · 최고관리자 기준 전체 업무 현황
[조회 월] [회사] [부서] [프로젝트] [데이터 소스] [JSON 불러오기] [JSON 내보내기]
```

### 통계 카드

4개 카드:

1. 진행 중 프로젝트
2. 납품 경과 프로젝트
3. 결재/승인 대기
4. 지연/충돌 업무

각 카드에 포함:

- 아이콘
- 주요 숫자
- 보조 지표
- 상태 설명
- 클릭 시 관련 페이지 이동 가능하면 연결

예시:

```text
진행 중 프로젝트
0
이번 달 0건 · 수정요청 0건
```

### 월별 프로젝트 요약

기존 문구:

```text
진행 중 프로젝트 요약
```

변경:

```text
월별 프로젝트 요약
```

컬럼:

- 프로젝트명
- 구분
- 상태
- 공정률
- 납품일/목표일
- 담당 PM
- 이슈
- 액션

### Empty State

데이터가 없을 때:

```text
아직 표시할 프로젝트가 없습니다.
JSON 데이터를 불러오거나 새 프로젝트를 등록해 주세요.

[JSON 불러오기] [수주 프로젝트 등록] [개발팀 작업 등록]
```

## 완료 조건

- 대시보드가 운영형 SaaS 화면처럼 보임
- 월별 프로젝트 요약 명칭 적용

# Phase UI-04 — 프로젝트 보드 디자인 개선

## 목표

프로젝트 보드를 실제 상태 관리 화면처럼 개선한다.

## 현재 문제

- 보드 필터바가 정리되지 않았다.
- 빈 보드가 너무 크게 보인다.
- 컬럼 카드 디자인이 단순하다.
- 수정 컬럼, 작업 착수 전 컬럼 등 기존 요구사항이 시각적으로 정리되어야 한다.

## 개선 방향

### 상단 Toolbar

```text
프로젝트 보드
[외부 수주 프로젝트] [개발팀 작업]
[프리셋 선택] [월 선택] [보기 방식] [개인일정 표시]
```

### 기본 보드 컬럼

```text
작업 착수 전
진행 중
수정
완료
```

각 컬럼 헤더:

- 컬럼명
- 카드 수 badge
- 평균 공정률 또는 이슈 수

### 납품일 임박도 보드

불필요한 가로 스크롤 제거.

컬럼 기준:

```text
납품일 경과
납품 1주일 전
납품 2주일 전
미정
```

또는 기존 정책에 맞춰:

```text
납품 1주일 전
납품 2주일 전
납품 1달 전
미정
```

단, 과거 납품일은 절대 `납품 1주일 전`으로 표시하지 말고 `납품일 경과`로 처리한다.

### CSS 기준

```css
.board-grid {
  display: grid;
  grid-template-columns: repeat(4, minmax(0, 1fr));
  gap: 16px;
  width: 100%;
}

.board-column {
  min-width: 0;
  overflow: hidden;
}

.board-card-list {
  overflow-y: auto;
  overflow-x: hidden;
}
```

## 완료 조건

- 4개 컬럼이 화면 안에 자연스럽게 배치됨
- 가로 스크롤이 불필요하게 생기지 않음
- Empty Column 디자인 개선
- 빌드 오류 없음

# Phase UI-07 — 직원 일정표 디자인 개선

- sticky first column

- 프로젝트 업무 chip
- 셀 hover tooltip
- 셀 클릭 상세 패널
- table border를 연하게 변경
- row height 통일

### Empty Cell

납품일

## 목표

## 알림 센터 개선

```text

[모두 읽음 처리]
```

Empty State:

```text
새 알림이 없습니다.
결재 요청, 일정 충돌, 수정 요청이 발생하면 이곳에 표시됩니다.
```

## 설정 화면 개선

### 현재 문제

- 기본 정보와 앱 설정이 단순 박스 형태다.

### 개선 탭

```text
내 정보
인사카드
조직/부서
JSON 데이터
알림 설정
화면 설정
```

설정 화면에서는 다음을 확인할 수 있어야 한다.

- 현재 사용자 정보
- role
- 회사/부서/팀
- 데이터 소스
- JSON export/import
- 알림 수신 설정
- 사이드바 모드
- 화면 밀도

## 완료 조건

- 알림 센터 Empty State 개선
